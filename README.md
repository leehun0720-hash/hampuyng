# 함평군 국비 공모 제안서 작성 지원 시스템

전라남도 함평군 **행정 AI 전환(AX) 1단계** — 국비 공모 제안서를 외주에서 사 오는 대신 군이 직접 만드는 체계.

`함평군_행정AX_1단계_사업제안서_최종.pdf`(13쪽)를 분석해, 제안서가 약속한 **검수 대상 결과물 5종**과
**신뢰성·감사 대응 3중 장치**를 실제로 동작하는 시스템으로 구현했다.

---

## 실행

```bash
npm install
```

```bash
npm run dev
```

http://localhost:3000 에서 열린다. **API 키 없이 전 기능이 동작한다**(데모 모드).

데이터는 `data/` 아래 JSON 파일로 저장되며 최초 실행 시 제안서 기반 시드가 자동 생성된다.
초기화하려면 `data/` 디렉터리를 지우고 다시 실행하면 된다.

## 이 시스템이 제안서에서 가져온 것

### 검수 대상 결과물 5종 (제안서 4-1)

| # | 결과물 | 구현 위치 |
|---|---|---|
| ① | 제안서 작성 표준 업무 매뉴얼 | 표준 절차 7단계를 워크플로우로 강제 — `/drafts` |
| ② | 함평군 자료 창고 (200건 이상) | `/documents` — 한글 검색엔진 + 200건 카운터 |
| ③ | AI 활용 지시문 30종 | `/prompts` — 공고분석 6 · 자료수집 5 · 초안작성 9 · 검토보완 6 · 사후관리 4 |
| ④ | 사전 기획서 1부 | `/drafts` — 공고 전 사전 기획서 착수 (제안서 4-3 방식 ②) |
| ⑤ | 교육 이수 담당 공무원 2명 이상 | `/metrics` — 게이트① 조건으로 추적 |

### 신뢰성·감사 대응 3중 장치 (제안서 5-2) — 코드로 강제

| 장치 | 강제 지점 |
|---|---|
| ㉮ AI는 자료 창고 안에서만 근거를 찾는다 | 모든 AI 호출이 `src/lib/ai/index.ts`를 거친다. 검색 → 근거 블록 → 가드레일 순서를 우회할 경로가 없다 |
| ㉯ 생성된 문장마다 출처 표기 | `[Dn]` 마커를 문서로 되돌려 배지로 렌더하고, 출처 없이 사실을 주장한 문장을 색출한다 (`src/lib/citations.ts`) |
| ㉰ 검토 확인목록 통과 없이 제출 불가 | 자동 검사 4항목은 **서버에서 다시 계산**한다. 체크박스를 임의로 켜거나 잠긴 버튼을 강제로 눌러도 서버가 거부한다 (`src/app/actions/review.ts`) |

### 데이터 등급 규칙 (제안서 5-2)

1등급(공개자료)·2등급(내부자료)만 등재된다. **3등급(대외비)·4등급(개인정보)은 등재 자체가 차단**되며,
차단 시도도 감사 이력에 기록된다. 3·4등급 자료가 창고에 없으므로 외부 AI로 전송될 가능성 자체가 없다.

### 확인되지 않은 숫자를 확정치로 쓰지 않는다 (제안서 맺음말)

- 시드 문서마다 `확인됨 / 확인 필요 / 가정치` 배지와 원출처(제안서 쪽수)를 표기한다
- ROI 전제값 6개는 모두 화면에서 수정 가능하며, 각각 확정 시점(`1단계 실측` / `3단계 실증` / `착수 시 확인`)을 함께 표시한다
- 실측되지 않은 절감률은 **`산출 불가`로 표시**한다. 임의의 숫자를 채우지 않는다

## 5분 시연 시나리오

1. **대시보드** (`/`)
   게이트① 3개 조건이 모두 **미충족** 상태로 시작한다. 제안서 5-1의 안전장치("게이트①을 통과하지
   못하면 2단계로 가지 않는다")를 그대로 보여준다. 5축 진단은 평균 2.1 → 목표 3.5.

2. **공고문 분석** (`/announcements`)
   `예시 공고문 불러오기` → `공고문 분석 시작`.
   배점표에서 평가항목 5개(합계 100점)를 추출하고, 항목마다 자료 창고에서 함평군 대응 근거를
   자동으로 붙인다. 근거가 없는 항목은 🔴로 표시되고 "자료 보강 필요" 목록에 쌓인다.

3. **초안 작성** (`/drafts/[id]`)
   `이 공고로 초안 작성 시작` → 각 단계의 `AI 초안 생성`.
   표준 절차 7단계가 자료 창고 근거만으로 채워지고, 문장 끝에 `[D1]` 출처 배지가 붙는다.
   근거로 채울 수 없는 항목은 `[확인 필요]`로 남는다 — 추정치를 만들어내지 않는다.
   각 단계 하단에 **AI에 전달된 근거 목록**이 표시된다. 이 범위 밖의 자료는 전달되지 않았다는 증거다.

4. **검토·제출** (`/review/[id]`)
   자동 검사 4항목이 통과해도 **사람 검토 없이는 제출 버튼이 잠겨 있다**.
   담당자 확인 항목을 체크하지 않고 검토를 기록하면 `미충족 5건`으로 거부된다.
   전 항목 충족 후에야 제출이 확정되고, `감사 대응 리포트`를 내려받을 수 있다.

5. **성과 측정** (`/metrics`)
   ROI 3시나리오가 제안서 7-2와 동일하게 나온다 — 보수 30개월 / 중간 9개월 / 적극 5개월.

### 차단 동작 확인 (선택)

- `/documents` → `+ 자료 등재` → 데이터 등급을 **4등급**으로 선택 → 버튼이 `등재 불가`로 잠긴다
- `/review` 하단 **전체 활동 이력**에서 차단·생성·검토·제출 기록을 확인한다

## AI 모드 3가지 (제안서 4-4)

제안서는 적용 AI를 "젬마4 또는 외부 상용 AI — 보안 요건 확인 후 착수 시 확정"으로 밝혔다.
따라서 특정 모델에 묶이지 않도록 설계했다. `/settings`에서 전환한다.

| 모드 | 동작 | 자료 전송 범위 |
|---|---|---|
| **데모** (기본) | 규칙 기반 처리 | 외부 전송 없음 |
| **Claude API** | Messages API 직접 호출 | 자료 창고 검색 결과 + 지시문만 |
| **로컬 설치형** | OpenAI 호환 엔드포인트 (Ollama/vLLM) | 내부망을 벗어나지 않음 |

데모 모드도 실제 AI 모드와 **동일한 제약**(자료 창고 한정, 출처 마커, `[확인 필요]` 표시)을 지킨다.
따라서 데모에서 본 화면 구조가 실제 운영과 달라지지 않는다.

API 키는 `data/settings.json`에만 저장되고 화면에는 마스킹된다. 이 파일은 `.gitignore`에 포함되어 있다.

## 설계 노트

**의존성 최소화** — `next` / `react` / `tailwindcss` 외 런타임 의존성이 없다.
차트는 자체 SVG, 저장소는 JSON 파일, AI 호출은 `fetch` 직접 사용(SDK 미사용).
군청 내부망 단독 서버 배포를 전제로 네이티브 빌드가 필요한 패키지를 배제했다.

**한글 검색엔진** (`src/lib/search.ts`) — 형태소 분석기는 무거운 네이티브 의존성이 필요해 배제하고,
**음절 bigram + 공백 토큰 혼합 BM25**로 구현했다. `자연재해위험개선지구` 같은 복합명사의 부분 일치와
`43.1%`, `2027` 같은 숫자 토큰의 정확 일치를 모두 잡으며 완전 오프라인으로 동작한다.

**단계별 근거 검색** — 단계 제목으로 검색하면 제목에 7개 단계명이 모두 들어 있는 절차 문서가
모든 단계에서 1위로 올라와 7개 단계가 똑같은 근거를 물어온다. 그래서 `DRAFT_STEPS.evidenceQuery`에
단계별 **내용 주제어**를 따로 두었다.

**AI 처리 시간 ≠ 담당자 실투입 시간** — 자동 계측은 AI가 처리한 시간만 잰다. 여기에는 담당자의
검토·보완 시간이 빠져 있어, 그대로 절감률에 넣으면 "16시간 → 1분, 99.9% 단축" 같은 무의미한 수치가 나온다.
제안서 2-2도 개선 후 담당자 실투입을 **18시간**으로 잡았다 — 작성 시간은 줄지만 검토 시간은 오히려 는다.
따라서 **게이트①의 절감률은 담당자가 직접 실측해 입력한 값으로만 산출**하고,
AI 처리 시간은 참고값으로 분리해 표시한다.

**JSON 저장소의 동시성** — Next.js는 한 화면에서 여러 `read()`를 동시에 실행하고 서버 액션도 병렬로 들어온다.
컬렉션 단위 큐로 직렬화해 (1) 시드 생성 시 임시 파일 rename 충돌과 (2) `update()`의 읽기-수정-쓰기 사이
갱신 유실을 막았다 (`src/lib/db.ts`).

## 배포 시 주의 — 서버리스 호스팅에서는 자료가 저장되지 않는다

이 시스템은 **군청 내부망 단독 서버**에 설치하는 것을 전제로 `data/` 디렉터리에 직접 기록한다.
Netlify Functions·Vercel 같은 서버리스 호스팅은 파일시스템이 읽기 전용이라 저장이 불가능하다.

저장 위치는 **시작할 때 실제로 파일을 써 보고** 결정한다. 오류 코드로 추측하지 않는다
(호스팅마다 코드가 달라 폴백이 걸리지 않는 사고가 있었다).

| 순위 | 위치 | 지속성 | 용도 |
|---|---|---|---|
| 1 | `<프로젝트>/data` | 영구 저장 | **실제 업무** — 로컬·내부망 단독 서버 |
| 2 | `<임시디렉터리>/hampyung-ax-data` | 인스턴스가 사는 동안 | 서버리스(Lambda `/tmp` 등) |
| 3 | 메모리 | 요청 간에만 | 위 둘 다 불가능한 경우 |

2·3번에서는 화면 상단에 **임시 저장 모드** 경고 배너가 뜨고, 서버 로그에 실제 사유가 남는다.
`HAMPYUNG_EPHEMERAL=1`로 메모리 모드를 강제할 수 있다(동작 확인용).

저장소 오류는 화면 밖으로 던지지 않는다. 자료 창고 하나가 깨졌다고 전체 화면이 500으로 죽는 것보다,
시드 데이터로라도 화면이 뜨고 로그에 원인이 남는 편이 낫다고 판단했다.

실제 운영에서 여러 담당자가 함께 쓰려면 JSON 파일 저장소를 데이터베이스로 교체해야 한다.
교체 지점은 `src/lib/db.ts`의 `read` / `write` / `update` 세 함수뿐이다.

## 범위 밖 (제안서 4-5와 동일한 선)

시스템 개발·서버 구축, 한글(HWP) 파일 직접 생성, 사용자 인증·권한, 운영·유지보수는 포함하지 않는다.
초안은 **한글 붙여넣기용 텍스트**와 마크다운으로 내보낸다.

시드 데이터는 제안서에 실제로 기재된 수치만 사용했다(28건). 실제 운영 시 게이트①의 200건을 채우려면
군 보유 자료를 추가로 등재해야 한다.
